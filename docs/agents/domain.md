# Domain docs

This project uses a single-context layout: root `CONTEXT.md` and `docs/adr/`.

Before exploring, read available `CONTEXT.md` and ADRs relevant to the work. If these do not exist, proceed silently without blocking or creating placeholders. Create domain records when terminology or architectural decisions are actually resolved.

Use established glossary terms in issues, specifications, tests, and implementation. Avoid drifting to synonyms. Note genuine vocabulary gaps for later domain modeling.

Surface contradictions with existing ADRs explicitly, identifying the ADR and why reopening it may be appropriate. Do not silently override recorded decisions.
